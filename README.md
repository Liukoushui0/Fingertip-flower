# 指尖花 · Fingertip Bloom 使用说明

这是基于 [TS-jj/fingertip-bloom](https://github.com/TS-jj/fingertip-bloom) 提交 `68b071b68d6053b1001d06b603c206f3e1c06505` 的本地复刻版本，并扩展了双手控制、立体翻滚、流风粒子、指尖移光、捏合换色和震屏散花手势。

项目用摄像头识别手部关键点，把手掌开合程度映射为粒子花朵的开花程度，并用掌宽、手掌朝向和手部位置控制缩放、旋转与空间视差。没有摄像头或没有授权摄像头时，仍然可以使用鼠标或手指控制花朵。

## 功能

- 多层粒子花瓣从花苞连续展开为完整花冠。
- 张手绽放、握拳收拢，手势开合程度连续变化。
- 左右转动手掌控制整朵花旋转，花瓣和粒子会同步转向。
- 手部左右位置控制立体翻滚，花盘会绕竖直轴侧翻。
- 手掌靠近或远离摄像头控制轻微缩放，并用横纵位置制造空间视差。
- 手掌快速横扫会产生风力和惯性，手停下后花朵会过冲并回摆。
- 横扫时会带出可随时间流动的碎光和风线粒子。
- 食指单独指向会移动花瓣高光，光源位置跟随食指尖。
- 拇指与食指捏合切换配色，带释放条件和冷却时间，减少误触。
- 快速握拳再张开会让整屏震颤，花朵散开数秒后自动重聚。
- 可在“单手”和“双手”控制之间切换。
- 鼠标、触摸屏和摄像头三种控制方式。
- 多套配色自动轮换，也可以手动切换。
- 保存纯画作截图，不包含界面元素。
- MediaPipe 模型和 WebAssembly 运行时已放在 `vendor/` 中，不依赖在线模型。
- 启动失败、摄像头不可用和解码加载异常时，会降级到鼠标/触摸模式。

## 环境要求

- Windows。
- Python 3.9 或更高版本。
- 推荐使用最新版 Chrome、Edge 或开启摄像头权限的其他现代浏览器。

Python 必须能够从命令行启动。安装时建议勾选“Add Python to PATH”。项目不需要安装 pip 包，也不需要 Node.js。

## 启动

### 方式一：双击 VBS

双击 `启动花朵.vbs` 后，脚本会在隐藏窗口启动本地预览，并自动打开：

```text
http://127.0.0.1:8899/
```

该方式不会弹出命令行窗口。

### 方式二：双击 BAT

如果 VBS 被安全软件拦截，双击 `start.bat`。效果相同，但会保留一个命令行窗口，便于查看错误信息。

### 方式三：手动启动

在项目目录打开终端，执行：

```bat
py -3 serve.py
```

如果系统没有 `py` 命令，可尝试：

```bat
python serve.py
```

也可以指定端口：

```bat
python serve.py 9000
```

默认端口为 `8899`。如果端口已被占用，服务会从 `8899` 开始向后寻找可用端口。

> 不要直接双击 `index.html` 作为最终运行方式。浏览器通常禁止 `file://` 页面的摄像头权限，此时只能使用鼠标或触摸控制。

## 扩展手势

扩展手势与原来的开合控制可以同时使用，不需要先进入单独模式。

### 旋转

把整只手掌当作方向盘，保持手掌朝向摄像头，绕手腕左右转动。程序取“手腕到中指根部”的连线方向作为滚转角度，再平滑映射到花朵旋转。

- 手掌竖直：花朵回正。
- 手掌向右倾斜：花朵向对应方向旋转。
- 手掌向左倾斜：花朵向反方向旋转。
- 旋转范围限制在约 ±77°，左右转动时变化更明显。
- 花朵不会无限累计角度；松开或离开画面后会平滑回到正向。

### 左右立体翻滚

除了手掌自身滚转造成的平面旋转，手掌在画面中向左或向右移动还会让花盘绕竖直轴侧翻。这样可以看到花瓣前后层逐渐错开，而不是整幅图案简单地左右平移。

- 手在中央：花盘正向面对观察者。
- 手向左移动：花朵向一侧立体翻转，最高约 ±53°。
- 手向右移动：花朵向另一侧翻转。
- 手掌横扫过快时，同时还会叠加风力和惯性回摆。

### 远近缩放

手掌靠近摄像头时，视觉上的手掌宽度增加，花朵放大；远离时缩小。缩放范围限制在约 68%–135%，避免不同人手型或摄像头焦距造成极端尺寸。

这个缩放是相对变化，不是精确测距。它适合制造“推近画面”的感觉，不应作为真实的距离测量。

### 横扫风与惯性

手掌快速水平扫过画面时，花朵会明显顺着横扫方向倾斜和位移，外层花瓣与花粉的落差大于花心。手掌停止后不会马上定住，而是经过较明显的过冲和阻尼回摆后恢复。

- 风力来自手的横向速度，不是手的绝对位置。
- 慢慢移动主要产生视差，快速横扫才会形成明显风力。
- 风越大，周围碎光和风线粒子出现的数量与亮度越高。
- 风线会沿横扫方向持续流动，而不只是随花朵整体平移。
- 手势短暂丢失时会保留剩余惯性，然后自然衰减。
- 食指指向移动光源时不会同时制造风力，避免两种动作互相干扰。

### 食指指向移光

只伸出食指、收起中指、无名指和小指，就可以用食指尖控制花朵上的局部光源。

- 光源会平滑追随食指尖，不会生硬跳动。
- 光源影响范围和高光强度已经加大，会形成更容易观察到的暖色局部高光。
- 单手模式下，检测到指向动作后会先暂停开合、旋转和缩放，把控制权交给光源。
- 双手模式下，一只手可以保持花朵控制，另一只手单独指向移光。
- 收回指向动作后，光源逐渐淡出，花朵恢复原来的整体照明。

### 捏合换色

保持其他手指舒展，用拇指和食指做一次明确的捏合动作，然后松开。每次完整的“捏合—松开”只会切换一次配色。

- 手掌必须处于较张开的状态才会触发。
- 捏合后需要先松开，才能进行下一次换色。
- 两次触发之间至少有 0.9 秒冷却。
- 普通握拳不会触发换色，因为触发条件要求开合度较高。

### 震屏散花重聚

这是独立的特殊动作：

1. 快速握拳，使平均开合度低于约 22%。
2. 在约 0.72 秒内重新张开手掌，使平均开合度高于约 78%。
3. 屏幕先短促震颤，随后全部粒子向外飞散。
4. 散开的粒子维持片刻，再自动回到原来的花瓣位置。

完整过程约 4.4 秒，触发后有约 6.2 秒冷却时间。

- 单手模式下，一只手完成“握拳—张开”即可。
- 双手模式下，两只手都参与平均开合度计算，因此需要双手一起完成动作。
- 没有摄像头时，双击画面也可以预览这段效果。
- 开启系统的“减少动态效果”后，会关闭整屏位移震颤，并降低散开幅度。

### 组合操作

| 想实现的效果 | 动作组合 |
| --- | --- |
| 缓慢绽放并旋转 | 逐渐张开手掌，同时绕手腕转动 |
| 让花朵靠近观察 | 保持张开，手掌缓慢靠近摄像头 |
| 让花朵被风吹动 | 张开手掌后快速向左或向右横扫，再停下看回摆 |
| 让花朵左右翻滚 | 手掌在镜头中向左或向右移动 |
| 触发散花重聚 | 快速握拳后立刻张开；双手模式需要双手同时完成 |
| 照亮某一侧花瓣 | 其他手指收拢，只伸出食指并移动到目标区域 |
| 收成花苞并回正 | 握拳，随后把本来的手移出镜头或把手掌转回竖直 |
| 切换配色 | 保持手指舒展，拇指与食指捏合后松开 |

界面左下方会显示当前开合百分比、旋转角度、立体翻滚角度和缩放比例。捏合成功或触发散花时，状态行会短暂显示对应动作。

### 减少误识别

- 手与摄像头之间保持约 40–80 厘米距离，并让手掌完整进入画面。
- 避免在逆光或强侧光下识别，手部轮廓过暗会让关键点跳动。
- 做旋转动作时保持手掌大致朝向摄像头，不要让手背完全转过去。
- 不使用换色功能时，拇指和食指自然分开，避免无意捏合。
- 手势识别存在正常延迟；动作应持续约半秒，不要快速来回甩动。

### 第二只手识别不出来

- 两只手都要完整进入镜头，手腕、指根和指尖尽量不要贴边。
- 两只手之间保留一点距离，不要互相遮挡。
- 保持两掌朝向摄像头，避免一只手侧转过大。
- 检查摄像头预览标签是否显示 `1/2 HANDS` 或 `2/2 HANDS`。
- 修改代码后需要关闭旧页面并重新打开，已加载的旧手部模型不会自动替换。
- 当前双手检测置信度门槛已经调低到 `0.32`。如果光线仍然过暗，应改善正面照明；继续无限降低门槛会增加误识别。

## 单手与双手控制

工具栏中的“单手 / 双手”按钮显示当前模式。点击后会立即切换；如果摄像头尚未启动，进入双手模式时会尝试启动摄像头。

### 单手模式

一只手的姿态同时控制多项效果：

- 开合度控制绽放。
- 手掌滚转控制旋转。
- 手掌远近控制缩放。
- 手掌位置控制视差。
- 手掌横向位置控制立体翻滚。
- 横向速度控制风力和惯性。
- 快速握拳再张开触发震屏散花。
- 食指指向控制光源。
- 拇指与食指捏合控制配色。

当这只手进入食指指向状态时，花朵的开合、旋转和缩放会暂时冻结，优先响应该手的移光动作。

### 双手模式

双手模式使用两只手共同控制，但会让每只手承担不同角色：

| 控制量 | 双手模式计算方式 |
| --- | --- |
| 花朵绽放 | 对所有未指向的手计算平均开合度 |
| 花朵旋转 | 对所有未指向的手计算平均滚转角度 |
| 花朵缩放 | 根据两只手中心点之间的距离计算 |
| 风力 | 根据双手中心点的横向移动速度计算 |
| 光源 | 任一只手进入食指指向状态，取第一个检测到的指向手 |
| 换色 | 任一非指向手完成捏合动作 |
| 空间视差 | 根据所有可见手的中心位置计算 |
| 左右翻滚 | 根据双手中心点的横向位置计算 |
| 散花触发 | 双手都参与平均开合度的“握拳—张开”检测 |

如果切到双手模式后只检测到一只手，页面会继续使用这只手控制，并在左侧显示“检测到 1/2 只手”。重新看到两只手后会自动进入双手协同，不需要再次点击按钮。

摄像头预览左上角会显示当前识别数量：

- `0/2 HANDS`：双手模式下暂时没有识别到手。
- `1/2 HANDS`：只识别到一只手，当前临时按单手控制。
- `2/2 HANDS`：两只手都已识别，进入完整双手协同。

第一只手的骨骼使用粉红色，第二只手使用紫色。两条骨架都显示，才说明预览层和识别层都正确取得了两只手。

双手模式使用同一个手部模型，主要增加的是每帧处理两只手关键点的计算量。低性能设备若出现明显卡顿，可以优先使用单手模式。

## 摄像头说明

摄像头 API 只会在安全上下文中开放。本地使用时应访问：

```text
http://127.0.0.1:8899/
```

或：

```text
http://localhost:8899/
```

如果手机通过 `http://192.168.x.x:8899/` 访问，浏览器通常不会提供摄像头 API，此时页面会使用触摸控制。若手机需要使用摄像头识别，需要浏览器认可的 HTTPS 安全页面。

第一次启用摄像头时，浏览器会询问权限，请选择“允许”。如果曾经误点“拒绝”，需要到浏览器的网站权限设置中重新允许摄像头。

## `serve.py` 提供的本地能力

- 为 `.mjs` 返回正确的 JavaScript MIME。
- 为 `.wasm` 返回 `application/wasm`。
- 为手部模型返回二进制 MIME。
- 支持音频 `Range` 请求。
- 通过 `/__lanip` 返回当前设备的局域网地址，供页面显示。
- 端口被占用时自动寻找后续可用端口。

该服务仅供本机和可信局域网内使用，没有登录认证，不要在公共网络或互联网上暴露端口。

## 常见问题

### 双击后没有反应

先在终端运行 `python --version`。

- 提示找不到命令：安装 Python 3，并把 Python 加入 PATH。
- 能显示版本但页面没有打开：改用 `start.bat` 启动，观察命令窗口中的报错。
- 端口被占用：服务会自动使用后续端口，请查看命令窗口打印的地址。

### 页面能打开但没有摄像头画面

- 确认地址是 `127.0.0.1` 或 `localhost`。
- 检查浏览器地址栏旁的摄像头权限。
- 关闭占用摄像头的会议软件、录制软件或其他浏览器页面。
- 在没有可用摄像头时，页面仍可使用鼠标或触摸模式。

### 没有声音

浏览器会限制自动播放音频。点击页面底部的“音乐”按钮，或按页面提示点击一次屏幕。音频文件位于同目录的 `bloom.mp3`，不要重命名，除非同步修改 `index.html` 中的引用。

### 页面卡顿

项目已经包含粒子数量、渲染倍率和移动端降级策略。低性能设备上可以继续调低 `index.html` 中 `LAYERS`、粒子生成数量以及设备像素比上限。

降级顺序以清晰度优先：桌面端先少量减少粒子，再降低渲染倍率，最低保持 `1.5×` 超采样；不会直接把高 DPI 画面降到 `1×`。无风时风线粒子也会降为接近不可见，避免整朵花笼罩在一层细雾中。

## 调整入口

主要参数都在 `index.html` 中：

| 想调整的内容 | 搜索位置 |
| --- | --- |
| 花朵大小 | `pxPerUnit` |
| 花瓣形状 | `const PATH` |
| 花瓣层数和数量 | `const LAYERS` |
